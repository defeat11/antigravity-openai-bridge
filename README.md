# antigravity-openai-bridge

[English](README.en.md)

**يستقبل طلبات أي عميل OpenAI قياسي، ويعيد ردود Gemini من Antigravity ACP CLI ببث SSE حقيقي.**

خادم Node واحد بلا أي تبعية خارجية: **1,711 سطر جافاسكربت**
(قياس: `wc -l server.js backends/*.js`) و`"dependencies": {}` في package.json.
يفتح 9 مسارات HTTP، أهمها `/v1/chat/completions` متوافق مع عملاء OpenAI SDK.

> ملاحظة صريحة: الجسر لا يعمل وحده. يحتاج
> [antigravity-acp](https://github.com/defeat11/antigravity-acp) المنشور على نفس الحساب،
> ووحدة `gemini-acp.js` التي تصدّر `GeminiAcpClient`، وأداة `agy` مثبتة محلياً.

## المشكلة

Antigravity CLI وكيل برمجة تفاعلي. يقرأ نصاً ويكتب نصاً عبر stdio فقط.

لا يوجد فيه HTTP، ولا توافق OpenAI، ولا نداء أدوات (tool calling).
وذاكرة جلسته تموت مع موت العملية.

في المقابل، كل العملاء الجاهزين يتكلمون OpenAI: أي OpenAI SDK،
وواجهات مثل Open WebUI، وأطر الوكلاء التي ترسل `tools[]` وتنتظر `tool_calls`.

## كيف يشتغل

```
عميل OpenAI (SDK / واجهة ويب / إطار وكلاء)
  └─ server.js                    9 مسارات، بث SSE، أرشفة المحادثات
      └─ backends/acp.js          يبني البرومبت ويدير الجلسة والحدود
          ├─ backends/toolbridge.js   بروتوكول نداء الأدوات النصي
          └─ gemini-acp.js (خارجي)    عميل ACP عبر stdio
              └─ antigravity-acp      المحوّل
                  └─ agy              النموذج نفسه
```

| الملف | الأسطر | الدور |
|-------|--------|-------|
| server.js | 881 | المسارات، SSE مع نبضة كل 15 ثانية، صندوق أسود للانهيارات |
| backends/acp.js | 469 | بناء البرومبت، نافذة آخر 20 دوراً، حارس ضد تكرار نداء الأداة |
| backends/session-anchor.js | 201 | تثبيت محادثة agy واحدة تنجو من إعادة تشغيل الخادم |
| backends/toolbridge.js | 160 | تحويل مخططات الأدوات إلى بروتوكول نصي وإعادة قراءة النداء |

ملفا اختبار مرفقان يشغّلان OpenAI SDK الحقيقي ضد الخادم:
23 فحصاً بالمجموع (قياس: `grep -c "check(" *.mjs` يعطي 14 + 9).

## أهم قرار في التصميم

**المشكلة:** أطر الوكلاء ترسل `tools[]` وتنتظر `tool_calls`،
والنموذج خلف ACP يعيد نصاً حراً فقط.

**القرار:** جسر أدوات نصي. تُصاغ مخططات الأدوات داخل البرومبت كبروتوكول صارم،
ويجيب النموذج بسطر JSON واحد عند حاجته لأداة، ثم يفكّه `parseToolCall`
إلى ردّ `tool_calls` قياسي. التنفيذ يبقى عند العميل، لا عند الجسر.

**التكلفة/العائد:** في وضع الأدوات يُجمَّع الرد كاملاً قبل الإرسال،
فيضيع البث حرفاً بحرف كي لا يتسرب JSON البروتوكول للمستخدم.
والعائد: أي إطار وكلاء OpenAI يعمل فوق CLI لا يعرف نداء الأدوات إطلاقاً.

### قرار عكسناه بعد القياس

بنينا «مرساة جلسة» تثبّت محادثة agy واحدة عبر `ACP_AGY_EXTRA_ARGS` فتنجو
الذاكرة من إعادة التشغيل. ثم سجّل تعليق في `server.js` الحادثة الحاسمة:
إعادة بثّ المحادثة المثبّتة عند الإقلاع أنتجت رداً واحداً بطول **280,901 حرف**
علّق الجلسة. ولأن العميل يرسل التاريخ كاملاً في كل طلب أصلاً،
صارت المرساة معطّلة افتراضياً وتُفعَّل بـ `GEMINI_SESSION_ANCHOR=on` عند الحاجة.

## التشغيل

```powershell
Copy-Item .env.example .env
node --env-file=.env server.js
curl http://127.0.0.1:3010/api/health
```

ولإبقائه حياً دائماً على ويندوز:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File keepalive-gemini3010.ps1
```

| المسار | الطريقة | الوظيفة |
|--------|---------|---------|
| /v1/models | GET | قائمة نماذج متوافقة مع OpenAI (كتالوج ثابت من 6 نماذج + الحي) |
| /v1/chat/completions | POST | محادثة كاملة: تاريخ، system، بث، أدوات |
| /api/think | POST | تفكير عميق بمهلة أطول ونموذج Pro |
| /api/health | GET | حالة جلسة ACP والمرساة |
| /api/reset | POST | إعادة تشغيل الجلسة مع حفظ المحادثة |
| /api/session/new | POST | نسيان متعمد: محادثة جديدة |
| /api/model | POST | تبديل النموذج النشط |
| /api/logs | GET | أرشيف المحادثات JSON |
| /logs | GET | صفحة عرض عربية للأرشيف |

كل القيم قابلة للضبط عبر 20 متغير بيئة موثقة في `.env.example`
(قياس: `grep -cE '^[A-Z]' .env.example`).

## لماذا بنيته

عملائي كلها تتكلم OpenAI، وواجهة Antigravity تفاعلية فقط.
الجسر جعل 6 نماذج Gemini متاحة لأي عميل قياسي دون تعديل سطر واحد فيه.
